# WhisperWrap Feature QA + UI/UX Report — 2026-08-23

Paired red-team/blue-team pass plus UI/UX review. Environment: `swift build` clean; `swift test` = 41/41 green (run outside the Claude sandbox). The GUI app was **not** launched in this environment — all "repro" columns are hand-traced from source; findings are marked **verified** (confirmed by build/grep/test run) or **inferred** (code-provable trace, not executed live). Static findings live in `AUDIT.md`.

## 1. Blue team summary (documented happy paths)

| Feature | Verdict |
|---|---|
| Global hotkey → recording toggle | WORKS (`DictationViewModel.swift:168`, Carbon registration `HotKeyManager.swift:70-90`; second fixed Opt+Shift+V shows last result) |
| Audio → WhisperKit transcription | WORKS (16kHz WAV → VAD trim → `WhisperTranscriptionEngine.transcribeToText`; concurrent model-load dedup + HUD download progress) |
| Auto copy to clipboard | WORKS (`DictationViewModel.swift:808-810`) |
| **Auto paste** | **FAILS — feature does not exist.** No CGEvent/paste synthesis anywhere, no "Auto Paste" setting (only Auto Copy, `DictationSettingsView.swift:54`); README:7,29 contradicted twice |
| Claude post-processing (dictation + file) | WORKS (prompt+text over stdin to `claude --print --model <m>`; streams to HUD; error-looking output falls back to raw) |
| File transcription drag-drop | WORKS (`TranscriptionView.swift:183` → `transcribeFormatted` txt/srt/json → moved next to input, revealed in Finder) |
| TTS (system + ElevenLabs) | WORKS (`TTSViewModel.speak()` line 212; real API calls, caching, playback) |
| Settings persistence incl. hotkey rebind | WORKS; limitation: hotkey recorder key map covers only A–Z/0–9, so a Space-based chord can't be re-picked in the UI |
| Model auto-download "on first launch" | Overstated — download happens on first *use* (or explicit prefetch), not at launch |
| Scripts | `generate_app.sh` and `uninstall_clean.sh` work; `simulate_login.sh` is stale (adjudicated below) |

**Adjudications:** Blue team initially passed `simulate_login.sh`; red team + static audit + an independent grep confirm `-backgroundLaunch` and `/tmp/ww_internal.log` appear nowhere in Sources and `LoggerService` is in-memory only — the script's log tail is dead and the flag is a no-op. **Ruling: stale (verified).** CLAUDE.local.md's claim that `CFBundleVersion = git rev-list --count HEAD` is also stale — the plist hardcodes `1` (verified, generate_app.sh:88-91). Double-hotkey-press was flagged by red team against the *menu-bar button* only; the hotkey path itself correctly guards (`isSelectingPrompt` → `isProcessing` → toggle, DictationViewModel.swift:428-441) — both passes agree, no conflict. No other red/blue conflicts.
